因子与 IC：把盘感变成可以验证的数

本章导读

你看盘时说"这票J值低、缩量、站在黄线上"——这句话里有三个因子。 本章讲清楚：什么是因子、怎么衡量一个因子"说话准不准"（IC）， 以及为什么你的系统里有13个子分数而不是1个。

1. 因子：对每只股票每天都能算出的一个数

为什么需要它？因为"图形好"没法批量比较5000只股票，而数可以排序。 量化做的第一件事就是把观察函数化：

def compute(df) -> Series   # 输入一段K线，输出每天一个数

因子分两类：布尔因子（今天满足/不满足，如"B1六条件全过"）和连续因子 （满足的程度，如"J值=-3.7比J值=12.9更超卖"）。你的系统从布尔升级到连续评分， 正是为了保留"程度"信息——两只都过B1的票，依然分得出谁更好。

类比

布尔因子像体检报告里的"合格/不合格"；连续因子像具体读数。 医生看到"血压不合格"会追问"多少？"——140和190完全是两种处理方式。选股同理。

2. IC：因子说的话，准不准？

有了因子，怎么知道它有没有用？答案是IC（信息系数）： 某一天，全市场每只股票的因子值，与它们未来N日实际涨幅的相关系数。 每天算一个IC，攒成序列再看均值——这就是截面检验。

  • |IC均值| > 0.03：可用因子；> 0.05：好因子；> 0.1：极强（罕见，警惕算错）
  • 实务用RankIC（排名相关），A股小票多极端值多，排名更抗噪
  • ICIR = IC均值÷IC标准差：不仅要准，还要稳定地准

IC的正负号同样有用：你系统里 N_STRUCT 的IC是 -0.387——强负相关， 意味着它是个优秀的反向过滤器（出现该形态后短期反而弱）。负IC不是坏因子，用反方向就行。

在你的系统里
  • 47个因子注册在 factor_registry.py，统一 compute(df)→Series 契约
  • 13个连续子分数（J低/趋势/缩量/红肥绿瘦/…/周线金叉/ML分）在 ranking/sub_scores.py，每个都把通达信条件"程度化"到0-1
  • 信号验证页跑的就是事件版IC检验：B1全历史71,687次信号、5日胜率47.5%、净均值+0.10%
  • 权重文件 config/factor_weights.json 未来由IC反馈自动调（FactorWeighter）

3. 因子的生命周期

因子会失效：拥挤（人人都用）、市场风格切换（小票年/大票年）、制度变化（涨跌幅、T+1）。 所以系统必须有反馈回路——你的信号追踪闭环（7日跟踪→连涨归因→沉淀）就是在持续重新校验因子。 一个健康的量化系统不是"找到圣杯然后躺平"，而是"不断给因子做年检"。

本章小结
  • 因子 = 把观察函数化成每天一个数；连续因子保留"程度"，优于布尔
  • IC = 因子值与未来收益的截面相关；|IC|>0.03可用，负IC反着用
  • ICIR衡量稳定性；因子需要年检，反馈回路比单次验证重要

自测

1. "当日J值"和"J值是否小于13"，哪个说法正确？
J值本身是个连续读数（-20到110都可能）；"是否<13"把它压缩成真/假，丢掉了程度信息。
2. 某因子IC均值=-0.06、ICIR=-0.8，正确的处理是？
|0.06|是不错的强度，负号只说明方向：因子值高→未来弱。反向用（做过滤或负权重）。你系统的N_STRUCT(IC=-0.387)正是这么用的。
3. 为什么A股实务更常用RankIC而非普通IC？
一只10倍妖股的原始收益会扭曲皮尔逊相关；换成排名后它只是"第1名"，影响有界。
4. 你的系统把"缩量"做成 vol/MA40 的连续打分而非"是否缩到1/4"，主要好处是？
连续化的核心价值就是可排序——全市场打分选Top50，必须每个维度都有"程度"。
