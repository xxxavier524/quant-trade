## 二、核心架构与关键模块精读

### 2.1 架构

```
core/      # 配置(YAML)与日志
data/      # 数据引擎：baostock 8进程并行增量拉取 → SQLite，后复权
strategy/  # 策略抽象基类 + 6个策略
notify/    # 飞书 webhook 推送
main.py    # 日常增量模式(2~3分钟) / --backfill 全量回填(~12分钟)
```

策略基类约定：每个策略实现统一的 `match(df)->bool`（或筛选接口），主流程对全市场逐票应用并汇总排序推送。**增量更新设计**：SQLite 记录每票最后日期，只拉缺口——比我们每日全量读CSV更省时。

### 2.2 六大战法精读

| 策略 | 文件 | 逻辑要点 |
|---|---|---|
| 海龟突破 | turtle_trade.py | 收盘创20日新高 + 成交额过亿 + 阳线（防假突破诱多）+ 按当日涨幅排序 |
| 均线放量 | ma_volume.py | 均线纠缠/多头初期 + 量能突破（倍量于均量线） |
| 高而窄旗 | high_tight_flag.py | 欧奈尔旗形：先有短期接近翻倍的急涨旗杆，随后窄幅缩量整理数日，等待再突破 |
| 涨停洗盘 | limit_up_shakeout.py | 近期有涨停（主力确认）→ 缩量回踩不破关键位 → 再起阳线确认 |
| 跌停反包 | uptrend_limit_down.py | 上升趋势中遇跌停（恐慌洗盘）→ 次日反包阳线收复 |
| RPS突破 | rps_breakout.py | 欧奈尔相对强度：全市场N日涨幅排名百分位(RPS≥87等) + 创新高突破 |

**精读结论**：这套战法的共同语法是"主力行为确认（涨停/爆量/急涨）→ 洗盘（缩量回调/跌停/窄幅整理）→ 再确认（阳线/突破）"，与用户 B1→B2→B3 的"底部确认→放量确认→缩量锁仓"是同一个母题的不同方言。**涨停洗盘 ≈ 用户'单针下三十洗盘'的涨停版；高而窄旗 ≈ 砖型图中继形态的旗形版。**

### 2.3 工程细节

- baostock 后复权（hfq）：避免前复权历史价格漂移导致信号回测失真——**我们当前用 baostock 需核对复权方式一致性**

## 三、亮点技术拆解

### 亮点1：RPS 相对强度排名（欧奈尔体系的核心件）

`RPS_N = 全市场该股N日涨幅的百分位排名×100`。原理：强者恒强是A股短线统计上最稳的截面效应之一。**对用户体系的价值**：B1 是"底部左侧"信号，天然面临"弱者更弱"风险；叠加 RPS120/250 下限（如≥60）可以过滤掉长期弱势股的假底，而保留"强势股回调出B1"的高胜率子集。实现是纯截面 rank，一行 pandas。

### 亮点2：涨停洗盘三段式状态判定

涨停日(t0) → 洗盘段（缩量、不破t0开盘价/分位）→ 确认日（阳线放量）。它把"洗盘是否结束"操作化为：回调期间每日量 < 涨停日量的某比例 且 低点不破锚定位。**这正是用户"3/4阴量线"和"缩量阴"语义的程序化表达**，锚定位+量能上限双约束的写法值得抄。

### 亮点3：防诱多过滤器

海龟突破要求突破日必须是阳线且成交额过亿——单看突破价容易被冲高回落的假突破骗进。用户砖型图"横盘突破"买点同样需要这层过滤（突破砖必须由阳线+量能确认构成）。

### 建议2：把"高而窄旗"翻译为砖型图中继确认因子

`alphapulse/factors/tight_flag.py`：旗杆=N日涨幅>X%（如10日>25%），旗面=随后M日振幅<Y%且量能递减，突破=阳线创整理期新高。作为砖型图"中继"形态的旗形子类注册，并入砖型战法信号。工作量：**1天**。

### 建议3：洗盘段量化模板（服务B3与单针下三十）

抽象 Sequoia 涨停洗盘的"锚定位+量能上限"模板为通用函数：

```python
def washout_ok(df, anchor_idx, max_vol_ratio=0.5, anchor_price_col='open') -> bool:
    """anchor日(爆量阳/涨停/B2日)之后的回调段：
    每日volume < anchor日volume * max_vol_ratio（对应用户'缩量阴/3/4阴量线'）
    且 low > df[anchor_price_col][anchor_idx]（不破锚定位）"""
```

B3 锁仓条件与单针洗盘共用该模板，max_vol_ratio 网格搜索（0.4/0.5/0.6/0.75）。工作量：**1天**。

## 六、不取的部分及原因

- **SQLite存储**：CSV+parquet对我们够用，且与vnpy回测管线已打通，不折腾
- **逐票循环匹配主流程**：保持我们向量化范式，仅移植策略数学
- **海龟/RPS作为独立买点**：右侧追高战法与用户底部挖掘风格冲突，只取其中的过滤器/确认器部件，不引入整套追涨买点
- **跌停反包**：A股跌停板流动性风险大，与用户风格不符，仅记录思想
