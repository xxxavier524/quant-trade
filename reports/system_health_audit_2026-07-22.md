# AlphaPulse-A 全面体检报告（交易 + 程序双角度）

> 生成：2026-07-22 · 方法：9 维度多智能体扫描（4 维完成 + 主审独立复核）· 目标校准：年化 ≥10%

## 结论先行（残酷但诚实）

1. **系统这段时间基本处于"空转/失明"状态**。数据链路长期崩坏（外接盘断挂 2 周 + baostock 持续失败 + 覆盖率长期 <75%），近两周只有 **07-10、07-16 两天**真正出了票，且都是延迟补跑。
2. **没有任何"自动升级策略"在真正发生**。夜间调参已停用；周度 auto_retune"只建议不改参"且目标函数、门槛都是坏的；能写参数的脚本一个都没排程；因子监控是死代码；因子权重夜更是空操作；ML 模型冻结在 7-3。
3. **报表里的"选股成功率"不可信**。agent 决策对账是一个**冻结在 7-3 的死循环**（而且记录是亏的），pick_reviews.md **只记赢家**（幸存者偏差），success_stats 的"成功"定义是"5 日内任一收盘触及 +5% 即永久判赢"（路径最大值、无成本、分母还排除未结算）——系统性高估。
4. **盈利能力与年化 10% 目标方向相反**。方法学可靠的诚实回测：B1 v1 (2020-2025) = **年化 -12.37%，最大回撤 -72.25%，胜率 38.4%**。walk-forward 的 24%"命中率"是信号级统计，扣滑点/费/-10% 止损后组合期望为负，与 -12.4% 自洽。README 的 +9.31% 已作废，V1/V2 对比报告是空壳。

**判定：当前系统不具备实现年化 10% 的能力，且当前既拿不到可信的实盘反馈，也没有能自我纠偏的闭环。要谈盈利，先修数据链路与度量诚实性，再重建以"组合级回测收益"为目标的迭代闭环。**

## 二、这段时间是否有"自动升级策略"？—— 没有，是"剧场式升级"

| 机制 | 应该做的 | 实际 |
|---|---|---|
| 夜间参数优化 (`daily_auto_run.py:78`) | 回测评估后调参 | **已停用**："假评估函数已下线，等待真实回测评估接入" |
| 周度 `auto_retune.py`（唯一排程的调优） | 找到更优参数并生效 | 只 append markdown 建议，**从不写 best_params.json**；只搜 ±邻域；目标是"每持有日净收益"（与组合收益无关）；门槛是两指标同时 ≥15% 改善——机械上几乎不可达。每周固定输出"邻域最优，无调整建议" |
| `run_walk_forward.py` / `ic_weight_tuning.py --apply`（能写参数） | 定期跑 | **没在任何 plist 里**，纯手动 |
| 因子权重夜更 (`FactorWeighter`) | 按 IC 更新权重 | **空操作**：ic_history schema 不匹配（strategy-keyed vs date-keyed），每晚 `compute_weights` 返回 `{}`，权重文件原样重写 |
| `FactorMonitor`（因子剔除引擎） | 剔除失效因子 | **死代码**：无人调用；且 `col.startswith('f_')` 过滤，真实因子（j_low/vol_shrink…）无一命中 |
| ML/UMP 模型 | 定期重训 | **冻结在 7-3**；`train_ump` 从没产出被接受的模型；`ml_score` 权重 0.12 却无人刷新 |

另外两个真实的逻辑 bug：
- **`FactorWeighter` 用 `abs(IC)` 加权**（`factor_weighter.py:196`）——会把"稳定预测反了"的负 IC 因子当成强因子给大权重。
- **`run_walk_forward.py:166` 无条件覆盖 best_params**——不比较是否打败在任参数，一次噪声采样就能把生产参数换掉。

**而且真实边际在两周内衰减约 5.8 倍**：`best_params.json` 记录 7-4 时"近一年净均值 +1.68%"，7-19 retune 日志同参数只剩 +0.29%——边际在退化，却没有任何机制能反应。

## 三、选股成功率：能不能信？——不能全信

- **agent 决策对账 = 死循环**：`reports/agent_decisions.jsonl` 只有 **10 条，全是 trade_date 2026-07-03**（7-05 记录一次后再没写过，因为写入者 `run_agent_team.py` 根本不在 eod_pipeline 里）。之后每天"对账"都是重算这同一批 7-3 的票，还盖上"今天"的日期，且 07-13 起**每天重复 append 两次**。而这批票是**亏的**：1 日胜率 30%、3 日 0%/-8.57%、5 日组合 -8.06%。
- **pick_reviews.md = 只记赢家**：`distill_success` 只查 `status='success'` 写复盘，85 条全是 +5%~+20%，没有一条亏损案例。当作"我们的选股表现"看会被严重误导。
- **success_stats 分母诚实，但"成功"定义有毒**（`signal_tracker.py:232`）：只要 5 日内**任一收盘**触及 +5% 就永久判赢——这是"是否曾经涨到过 +5%"的路径最大值，不是可成交收益（涨到 +6% 又跌到 -20% 也算赢）；且入场按信号日收盘、零滑点零费（比系统自己"次日开盘 + 0.1%/0.2%"的口径乐观整整一天）；分母还排除仍在 tracking 的信号，而赢家往往第 1 天就结算、输家要等满 5 日数据（数据链坏常常等不到）——**结算时间差进一步抬高命中率**。

**能信的只有一个**：方法学可靠的组合级诚实回测（下节）。

## 四、长期盈利能力评估 vs 年化 10%

**回测引擎本身是可信的**（`run_backtest.py` 已复核）：次日开盘成交（:170/181）、开盘涨停 9.8% 与停牌跳过（:50/57）、买滑点 0.1%/卖 0.2%、-10% 止损（:249）、单票 ≤20% 最多 5 只、正确的 252 日年化（:284）、回撤/Sharpe/Calmar/Sortino 齐全。

| 口径 | 年化 | 最大回撤 | 胜率 | 样本 | 来源 |
|---|---|---|---|---|---|
| **诚实引擎 B1 v1（现存股）** | **-12.37%** | **-72.25%** | 38.4% | 787 笔 | `survivorship_bias_report.md` |
| + 退市股（真实占比 4.3%） | -12.34% | -75.59% | 37.3% | 853 笔 | 同上 |
| walk-forward 链式 OOS | "5 日内 +5% 命中率"中位 **24%** | —（非组合口径） | — | 5007 信号 | `walk_forward_B1_B2_B3.md` |
| README 旧表（**已作废**） | +9.31% | — | — | — | 乐观引擎（信号日成交/无涨停检查/估值 bug） |
| V1 vs V2 对比 | 全部"待补" | — | — | — | `backtest_comparison_report.md`（空壳，5-16 至今没填） |

**用回测方法学审视**（backtest-expert 视角）：
- **命中率 ≠ 期望**：24% 的信号能"摸到"+5%，意味着 76% 摸不到、其中相当部分走向 -10% 止损。24%×(≤+5%，还未必卖在高点) − 76%×(负收益，含 -10% 触发) − 往返滑点(≈0.3%)−费，**净期望为负**，与组合回测 -12.4% 完全自洽。
- **未过压力测试**：-72% 回撤本身就是"不可投资"级别；集中 ≤5 只放大尾部。
- **无正期望的样本外证据**：所有"看起来还行"的数字都是信号级命中率或每笔均值，一旦落到"次日开盘 + 成本 + 止损 + 仓位"的组合口径就转负。

**判定：以当前策略与参数，年化 10% 不可达，方向是负的。** 想达标必须先解决三件事（见第七节），其中"以组合级回测收益/Sharpe 为目标重做参数与因子筛选"是绕不过去的。

## 七、修复优先级（要谈盈利，按此顺序）

**P0 — 先让系统"不撒谎、不空转"**
1. `daily_screener` 加**数据新鲜度硬闸**：用交易日历/指数独立算真实最新交易日，众数日期落后 >1 交易日就**中止或明确标 STALE 且禁止推送**（修 C1/C2/H6）。
2. 修 15:30 覆盖率口径（用"个股 EOD 实际发布日"或 `max(last_date)` 判覆盖，而非指数盘中 bar），并**加并发锁 + 原子写进度**（修 H1/H3）；把 `recover_stale.py` 排程（H4）。
3. 排查**部署漂移**：让 launchd 从固定 checkout/记录 git hash 运行，确认 #4/#5 真的在跑（H2）。

**P1 — 让度量可信**
4. 重定义"成功"为**固定可成交退出**（如 D+1 开盘入、5 日收盘出，扣滑点费）下的收益分布；success_stats 分母纳入所有到期信号；pick_reviews 同时记录亏损案例（修 C4/C5/H8/M1/M2）。
5. 把 agent 决策写入接进 pipeline，或让对账在数据陈旧时明确标 STALE、去重（修 C3）。

**P2 — 重建真正的迭代闭环**
6. 把优化目标换成 **`run_backtest.py` 的组合级年化/Sharpe/回撤**（含涨停、成本、≤20%/5 只、零轴与大盘闸门），auto_retune 通过带样本外验收的门槛后**真的写参数**（修 C6/C7）。
7. 修 `is_red/is_green`（H5）、`abs(IC)`→有符号/截负、FactorWeighter schema、FactorMonitor 命名与接线；给边际衰减加告警/降险触发。

**P3 — 卫生**
8. 日志轮转 + 压掉 FutureWarning（M6）；删 friday_screener/after_close 死路径（L1）；清理 daily_auto_report 历史脏数据（L3）。

**关于年化 10%**：在 P0-P2 完成前，任何"命中率/每笔均值"都不能作为盈利依据。真正的问题不是调参能否从 -12% 拉到 +10%，而是**当前这套 B1/砖型/单针在诚实口径下没有正期望**——需要以组合级回测为准绳重新做因子/策略筛选，先把期望做正，再谈年化目标。
